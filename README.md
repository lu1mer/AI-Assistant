# AI Assistant

**Aster** — нативный AI-чат для iPhone на SwiftUI, iOS 18+.

> Статус: актуальная версия собрана в Debug и Release. Полный набор 20 unit + 7 UI тестов прошёл; отдельный настоящий OpenRouter UI-тест прошёл streaming, Stop, следующий вопрос и restart. Светлая/тёмная тема явно выбирается в приложении и сохраняется. Передаваемые логи и Git-история повторно очищены. Запуск на iOS 18 остаётся неподтверждённым: runtime недоступен в каталоге Xcode.

## Time

Около **1.55 часа** активного времени работы Codex, включая сборки, тесты, переход на OpenRouter, настройку ключа и финальный аудит. Оценка по временным меткам родных логов; длинные паузы исключены. Это время работы агента, не трудозатраты человека. Интервалы и метод расчёта — `docs/time.json`.

## Tools

- Codex desktop: `gpt-6-astra` для основной разработки, `gpt-6.1-sol` для настройки ключа и финального аудита (метаданные native sessions).
- Xcode 26.3 (17C529), Swift 6, XcodeGen 2.46.0.
- SwiftUI, SwiftData, Foundation/URLSession, XCTest/XCUITest.
- Сторонних зависимостей нет.

## AI Provider

- OpenRouter, `openrouter/free` (маршрутизатор только бесплатных моделей).
- HTTPS Chat Completions, `stream: true`, Server-Sent Events.
- Выбран за простой API, поддержку streaming и наличие бесплатного тарифа. [Streaming](https://openrouter.ai/docs/api/reference/streaming), [лимиты](https://openrouter.ai/docs/api/reference/limits).
- URLSession.AsyncBytes → SSEDecoder → AsyncThrowingStream → ChatViewModel.
- Лимит ответа: 2048 токенов. В запрос передаётся непустая история диалога; неудачные частичные ответы исключаются. При слишком большом запросе предлагается новый чат.
- API-ключ из исходного архива удалён при подготовке копии для GitHub. Следующие данные квоты относятся к первоначальной локальной версии: После всех реальных запросов осталось **44 из 50** бесплатных запросов на текущий UTC-день (05.10.2026, около 23:49 Москва). Платные расходы за день: 0. Данные проверки: `docs/quota-check.json`; лимит обновляется со временем.

### Настройка API-ключа

Перед первым запуском добавьте свой OpenRouter API-ключ через `ConfigureAI.command`. В копии для GitHub встроенный ключ удалён. Используется только бесплатный маршрутизатор, без платной запасной модели.

Для замены ключа разработчиком доступен `ConfigureAI.command` (скрытый ввод) или `Scripts/embed_key.py` с путём к файлу вне проекта. `Scripts/ConfigureAI.swift` — исходник отдельного macOS-окна настройки. XOR — обфускация, а не защита от извлечения ключа из клиента.

## Usability update

- Компактный список, поиск по названиям и содержимому сообщений. Ровная кнопка «Новый разговор» с областью нажатия минимум 56 pt.
- Меню темы справа сверху: «Как на устройстве», «Светлая», «Тёмная». Выбор сохраняется после закрытия приложения.
- Новый разговор непосредственно из чата.
- Копирование ответа с подтверждением и системное меню «Поделиться».
- Кнопка «Готово» над клавиатурой; после отправки клавиатура закрывается.
- Прокрутка следует за генерацией, пока пользователь не начинает читать историю; кнопка возврата к последнему сообщению.
- Подсказки показывают вопрос до выбора, вспомогательная подпись убрана из обычного поля ввода.

В актуальной версии прошли проверки поиска, копирования, нового чата, клавиатуры, тем и реального API. Снимки светлой/тёмной темы — `docs/screenshots/*-list-final.png`.

## Implemented

- Несколько разговоров: создать, открыть, переключиться, удалить с подтверждением.
- Настоящий SSE-клиент; постепенное отображение текста без искусственной задержки в production.
- Stop отменяет consumer/producer и сетевую сессию, сохраняет частичный ответ.
- Retry заменяет неудачный ответ без дублирования user message.
- SwiftData: история, порядок сообщений, даты, заголовок из первого вопроса, восстановление незавершённого ответа.
- Empty/loading/error states, понятные ошибки сети, timeout, HTTP, квоты и повреждённого/оборванного ответа.
- Светлая/тёмная тема, системные шрифты, Dynamic Type, клавиатура, длинные сообщения, прокрутка и переход к последнему сообщению.
- XcodeGen, Finder build/test scripts, последовательная Git-история и настоящие очищенные AI-логи.

## Not Implemented / Known Issues

- Конкретную бесплатную модель выбирает OpenRouter; доступность и лимиты провайдера могут меняться.
- iOS 18: deployment target выставлен, но runtime не установлен; проверка на самой iOS 18 не выполнена.
- UI automation при холодном запуске симулятора иногда пропускала первое нажатие; финальный полный прогон на одном симуляторе прошёл. Максимальный accessibility-шрифт и landscape прошли отдельную UI-проверку после исправления composer.
- Физический iPhone не использовался; device-signing требует Apple development team.
- Фото, Mac, offline Foundation Models не реализованы.
- Ответы отображаются как обычный текст с сохранением переносов, без расширенного Markdown/подсветки кода.
- Генерация останавливается при уходе с экрана/сворачивании приложения. Внезапное завершение процесса может потерять до 350 мс последних chunks; явно остановленный ответ сохраняется сразу.
- История локальная, без iCloud. Для небольшого тестового приложения сообщения каждого чата хранятся одним Codable payload; для очень больших архивов нужна другая стратегия хранения.

## Testing

Подробная матрица — [docs/testing.md](docs/testing.md). 20 unit-тестов и 7 UI-тестов прошли в полном актуальном аудите; отдельный LiveAI тест с настоящим API также прошёл; проверены сетевой parser, ошибки, cancellation, Retry, SwiftData, перезапуск, удаление и независимость чатов. Светлая и настоящая системная тёмная тема проверены по скриншотам. Проверки используют iPhone 17 Pro Simulator, iOS 26.3. SDK сборки — iOS 26.2, deployment target — 18.0.

`Test.command` запускает unit + UI suite на установленном iPhone Simulator. UI-тесты используют явный Debug-only `--ui-testing` режим и отдельное хранилище. Он не включается при обычном запуске и исключён из Release. В нём задержки имитируют поток только для проверок интерфейса.

Для добровольной повторной проверки настоящего API доступна схема `LiveAI` в Xcode. Она использует встроенный ключ и расходует бесплатные запросы. Обычный `Test.command` работает с фикстурами.

## Build

1. **Double-click `Build.command`.**

Требуются установленный Xcode с iOS SDK и XcodeGen (`brew install xcodegen` один раз при подготовке машины). Скрипт сам определяет папку, добавляет стандартные Homebrew PATH, генерирует проект, собирает Simulator app и пишет SUCCESS или понятную ошибку. В интерактивном окне ждёт Enter, чтобы результат не исчез.

Результат: `build/DerivedData/Build/Products/Debug-iphonesimulator/AIAssistant.app`. Для запуска можно открыть сгенерированный `AIAssistant.xcodeproj`, выбрать iPhone Simulator и нажать Run. Сборка не требует signing team.

Troubleshooting: открыть Xcode и принять лицензию; проверить Settings → Locations → Command Line Tools и Settings → Components. Полный build log — `build/build.log`. `CI=1 ./Build.command` отключает ожидание Enter. Для теста на конкретном runtime: `SIMULATOR_ID=<UDID> CI=1 ./Test.command`.

## Architecture

```text
Sources/
  App/                    composition root, startup recovery, debug fixtures
  Models/                 Codable Sendable conversation and message values
  Features/ChatList/      navigation and conversation list
  Features/Chat/          view, message row, MainActor view model
  Services/AI/            protocol, OpenRouter client, SSE decoder, domain errors
  Services/Persistence/   repository protocol, SwiftData, observable store
  Core/UI/                native visual components
  Resources/              app icon
Tests/                    parser, networking, state, disk persistence
UITests/                  full UI flows with deterministic dependencies
```

MVVM + service layer. SwiftData хранит один record на чат с упорядоченным Codable-массивом сообщений: атомарное сохранение без неявного порядка relationships. Repository единолично владеет ModelContext. ViewModel управляет одним активным запросом; отдельный request ID отсекает поздние callbacks после Stop/Retry.

`AGENTS.md` и `docs/` использованы до и во время разработки. `ai-logs/` содержит очищенный экспорт родной Codex-сессии. ZIP включает `.git`, исключает DerivedData, полные xcresult, пользовательские настройки Xcode и открытые API-ключи.

Переход на OpenRouter: используется только `openrouter/free`, без платной запасной модели. Конкретная бесплатная модель выбирается сервисом и может меняться. Исторические отчёты в docs/ относятся к предшествующей интеграции Groq, если явно не указано иначе.

Если ConfigureAI.command сообщает `Operation not permitted`, проверьте macOS → Системные настройки → Конфиденциальность и безопасность → Файлы и папки → Terminal → Документы. После разрешения доступа полностью перезапустите Terminal. Скрипт использует системный `/usr/bin/python3`, чтобы сторонний Python.app из PATH не перехватывал запуск.

## Privacy audit

Логи в ai-logs очищаются от ключей, bearer-токенов, пользовательских путей, имени устройства, email и изображений/base64. Очистка применена также к старым версиям логов в Git; этапы и даты коммитов сохранены, хэши изменились. Старые недостижимые Git-объекты удалены. Отчёт: `docs/security-audit.json`. Обфусцированный ключ в исходниках сохранён по ТЗ; его можно извлечь из клиента, поэтому такую схему не следует считать production-защитой секрета.

## Копия для GitHub

Встроенный API-ключ удалён. Перед запуском выполните `ConfigureAI.command`. Репозиторий импортируется с новым начальным коммитом: история из архива содержит встроенные учётные данные и не переносится. Отчёты о тестах в этом README и docs описывают исходную версию, а не новый прогон. После локальной настройки ключа не коммитьте сгенерированные значения в `EmbeddedCredential.swift`.
